## Up and running in a minute

<Tabs syncKey="pkg">
  <TabItem label="pnpm">
    ```sh
    npm install -g @tulipes/cli
    tulipes init my-api
    cd my-api && pnpm install && pnpm dev
    ```
  </TabItem>
  <TabItem label="production preset">
    ```sh
    # auth, users, settings, MongoDB, queues, sockets, PM2 and nginx
    tulipes init my-api --preset production
    cd my-api && pnpm install && pnpm dev
    ```
  </TabItem>
</Tabs>

Open `http://localhost:3000/api/v1/hello`. The minimal preset needs no
database, no Redis and no credentials.

## One feature, one folder

A module holds everything a feature needs: routes, permissions, settings,
models, jobs and sockets. Delete the folder and the feature is gone.

```ts title="modules/books/routes/web/books.routes.ts"
import { Router } from "express";
import { requireModels, type BackendCtx } from "@tulipes/core/boot";

export default function booksRoutes(ctx: BackendCtx): Router {
  const router = Router(); // mounted under config.api.prefix (/api/v1)

  router.get("/books", ctx.rai({ id: "books:web:list", name: "List books" }), // the id is the permission
    async (req, res) => {
      const books = await requireModels(ctx).get("Book").find().lean();
      res.respond({ data: books });                                          // one envelope everywhere
    });

  return router;
}
```

## When something is wrong, you hear about all of it

```txt
TulipesBootError: Boot aborted during "environment" — 3 issue(s):
  ✖ [core]  required variable "MONGO_URI" has no value
  ✖ [users] variable "USERS_MAX_SESSIONS": "abc" is not a number
  ✖ [users] required variable "USERS_ADMIN_EMAIL" has no value
```

Missing variables, dependency cycles, duplicate permissions and colliding
queue names stop the boot with one report. Ten problems is one crash, not ten restarts.

## Why Tulipes

<CardGrid>
  <Card title="Fail closed" icon="warning">
    Unknown roles are denied, unrouted requests get a 404, and internals never
    leak outside development. Every check that can run at boot does.
  </Card>
  <Card title="Typed from your code" icon="seti:typescript">
    `tulipes sync` generates types from your modules, so a wrong model name,
    job payload or environment variable fails to compile.
  </Card>
  <Card title="One codebase, three processes" icon="seti:config">
    The same app boots as an HTTP server, a queue worker or a one-off script,
    with the same modules and the same configuration.
  </Card>
  <Card title="Infrastructure you choose" icon="puzzle">
    Core installs no driver. Add MongoDB, BullMQ or Socket.IO as providers, and
    an app that needs none installs none.
  </Card>
  <Card title="Documented by declaration" icon="document">
    The schemas that validate a request also generate OpenAPI 3.1 and Postman
    collections, so the docs cannot drift from the code.
  </Card>
  <Card title="Ready for AI agents" icon="rocket">
    Modules declare actions an agent may call, gated by the same permissions as
    routes, and `@tulipes/mcp` serves them over MCP.
  </Card>
</CardGrid>
