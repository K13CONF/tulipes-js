# Forgex example app

The reference layout for a Forgex application. Everything in this folder is
**yours** — the framework itself lives in `@forgex/core` and you never edit it.

## Layout — what every piece is for

```
example/
├── app.ts                  web entrypoint      — boot({ mode: "web" }), ~3 lines
├── worker.ts               worker entrypoint   — boot({ mode: "worker" })
├── app.middleware.ts       GLOBAL MIDDLEWARE   — your slots in the request pipeline
├── config/
│   └── app.config.ts       app-wide config seed, runs before every module factory
├── lib/                    app-owned glue — cross-cutting helpers you shape freely
│   ├── cache/              Cache contract + memory (LRU-capped) and redis drivers,
│   │                       appCache() picks one from the environment
│   └── mongoose/           base plugins every model gets: snake_case timestamps,
│                           soft delete (is_deleted/deleted_at/deleted_by, auto-
│                           excluded from queries) — registerBasePlugins() in app.ts
├── modules/                the app itself: one folder = one feature = one package
│   ├── core/               tier "sys" — infra env vars, global roles
│   ├── auth/
│   └── users/
├── locales/                i18n dictionaries (planned)
├── types/
│   └── config.d.ts         GENERATED by `forgex sync` — do not edit
├── .envs/
│   └── .env.development    per-mode env files; APP_ENV picks one
├── .env.example            GENERATED — every variable any module declares
└── tsconfig.json
```

### Where does global middleware go?

`app.middleware.ts`, at the app root. The web request pipeline is fixed and
worth memorizing:

```
1. securityHeaders     core — nosniff, frame-deny, CSP
2. requestLogger       core — one line per request
3. express.json        core — body parsing
4. beforeRoutes(ctx)   ← YOU: auth gates, CORS, rate limiting, request ids
5. module routers      every modules/*/routes/*.routes.ts, in load order
6. afterRoutes(ctx)    ← YOU: rarely needed; sees requests no router claimed
7. notFoundHandler     core — turns the rest into a 404
8. errorHandler        core — terminal; catches async throws, hides
                       internals outside development
```

Middleware for **one module only** doesn't belong here — mount it on that
module's own Router inside its `*.routes.ts`.

### Where does app-wide config go?

`config/app.config.ts` — its result seeds the global config *before* any
module factory runs, so every module can read it (`ctx.config.app.name`).
Config that belongs to one module goes in that module's `module.config.ts`.

### What is lib/ for?

Cross-cutting helpers that are neither a feature (→ module) nor framework
(→ core): cache wrappers, mongoose conventions, date/format utilities.
Modules may reach into it with a relative import — it's deliberately not a
package, it's your app's shared drawer.

Two real examples ship with the skeleton:

- **`lib/cache/`** — a small `Cache` contract with two drivers: `RedisCache`
  (JSON-serialized, key-prefixed so it never collides with BullMQ) and
  `MemoryCache` (LRU-capped, for tests and redis-less runs). `appCache(env)`
  picks the driver from the environment; the sys core module's `onShutdown`
  closes it.
- **`lib/mongoose/`** — plugins every model gets via `registerBasePlugins()`
  (called in app.ts/worker.ts *before* boot, since global plugins only affect
  models compiled after registration): snake_case `created_at`/`updated_at`,
  and soft delete — `doc.softDelete(actor)` flags instead of removing,
  ordinary queries auto-exclude flagged docs, `.withDeleted()` /
  `.onlyDeleted()` opt out, hard `deleteOne`/`deleteMany` stay literal on
  purpose. Extend `BaseDocument` in model interfaces to inherit the typed
  fields and methods.

## Anatomy of a module

```
modules/users/
├── package.json            name + "forgex" key: tier / priority / dependsOn
├── meta.variables.json     every env variable this module needs (validated at boot)
├── module.config.ts        default-export: config factory; optional onReady/onShutdown
├── module.acl.ts           permission grants for this module's resources
├── routes/*.routes.ts      default-export (ctx) => Router
├── models/*.model.ts       default-export { name, schema }
├── bootstrap/*.bootstrap.ts  post-DB, pre-server tasks (indexes, seeds)
├── queues/*.queues.ts      default-export (ctx, queues) => define + process
├── sockets/*.sockets.ts    default-export (ctx, sockets) => claim namespaces
└── controllers/            convention only — routes import them directly
```

Modules load in order: tier `sys` first, then `priority` (lower first), then
`dependsOn` topological order. Every file above is optional except
package.json.

## Boot order (what runs when)

1. Environment: `.envs/.env.<APP_ENV>` + every `meta.variables.json` →
   validated variable store (crashes with ALL problems at once)
2. Module graph: sort + cycle detection
3. `config/app.config.ts` seed → every `module.config.ts` factory
4. ACL merge (roles from sys core, grants everywhere)
5. Database: connect → models → bootstrap tasks
6. Queues register (both modes)
7. **web**: pipeline above, sockets, listen · **worker**: start consuming
8. `onReady` hooks — shutdown runs everything in reverse

## Daily commands

| command | does |
|---|---|
| `yarn dev` / `forgex dev` | run web process (dev regenerates types first) |
| `yarn worker` | run queue-consumer process |
| `forgex sync` | regenerate `types/config.d.ts` + `.env.example` |
| `forgex env:check` | validate env without booting — CI gate |
| `forgex new module <name>` | scaffold a module |
| `yarn typecheck` | typecheck app against the generated types |
