# 0.13 measurements

The one number the 0.13 plan (§7) asked for, with the conditions that produced
it. It is a before/after of nothing and not a benchmark of the framework: only
how long an agent client waits for the MCP process to answer `initialize`.

## Cold start of the MCP process (S03)

**What:** time from `spawn` of `node mcp.ts` (what `pnpm mcp` runs) to the
`initialize` reply on stdout, with the request written to stdin at spawn. The
same installed app also ran `node app.ts` to the banner's URL, alternating with
the MCP runs, for scale. Five runs each, SIGTERM (stdin closed for the MCP
process) between runs, median reported.

**Where:** the production preset generated and installed from the packed
0.13.0-rc.1 archives by `scripts/scaffold-smoke.mjs .artifacts production`
with `TULIPES_SMOKE_KEEP=1` (its `test` step skipped on this Mac, see the
release record); macOS 14.5 (Darwin 23.5), Node 24.14.0, pnpm 10.28.0, MongoDB
7.0.12 and Redis 7.2.6 on localhost, `APP_ENV=development`, `PORT=0`, console
and file logging off, a fresh database per session.

| start | median | min | max |
|---|---|---|---|
| `node mcp.ts` to the `initialize` reply | 452 ms | 440 ms | 992 ms (first run, cold file cache) |
| `node app.ts` to the banner's URL | 438 ms | 424 ms | 730 ms (first run) |

Runs in order, MCP: 992, 440, 442, 452, 456 ms; HTTP: 730, 424, 429, 438,
447 ms.

**Reading it:** the MCP process boots the whole app in script mode (models,
module graph, providers) before it answers, so it costs about what the HTTP
backend costs to listen, 14 ms more at the median, and a client that registers
the server pays that once per session. The 0.11 production number on the other
machine (532 ms to the banner, 2026-10-08) is not comparable: different
hardware and OS, and a different app (the reference app, not the generated
starter). Not measured: Streamable HTTP's first request, a warm `tools/list`,
and the cost of `identify` on each call (it reads the user and the token row,
which the session cache serves in the reference app).

The script that took the numbers is short: spawn, write the `initialize` line,
read stdout until the line with `"id":0`, record `performance.now()` − start.
