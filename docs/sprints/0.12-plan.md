# 0.12 — a standard RAI format, roles with metadata, scope-first files

Status: **in progress** (see §9), proposed on 2026-10-12 against `d750eb8` (0.11.0),
with the maintainer's decisions recorded in the context section. Nothing
is implemented. Each sprint item in §7 is committed on its own after its
checks pass; this file is the tracker and gains the evidence as items land.

## Context

Today a RAI id is any `name:action` string (`packages/core/src/acl/acl.ts`
`RESOURCE`, `packages/core/src/agent/define-agent.ts` `ACTION_ID`). The
convention "namespace by module" exists only in prose, so ids drift
(`hello:greet-name`, `users:read-deleted`, `auth:session-end`) and nothing
says which client surface an endpoint serves. Roles are bare strings:
`defineRole("admin")` cannot carry a description or any other property, so
nothing downstream (CLI, spec, console) can explain a role.

Decisions taken with the maintainer (2026-10-12):

- Grammar is `{module}:{scope}:{resource}[:{extra}]`: three segments
  required, a fourth optional. **Exactly 3 or 4 segments.**
- Segments keep today's casing: `[a-z][a-z0-9-]*` (kebab allowed). The
  module segment is the module's short name as `package.json` spells it
  (`@app/user-profiles` → `user-profiles:…`).
- Scopes are **free-form** (no `defineScope`); the shape is validated, the
  vocabulary is the app's.
- Module ownership of the first segment stays a **convention**, not a boot
  check.
- Routes and controllers are named scope-first (§4b): a best practice the
  reference app follows, never a boot rule.
- The reference app uses two scopes: `web` (auth, hello, users
  self-service, the agent door) and `bo` (config, settings, users
  administration).
- `defineRole(name, { description, ...anything })`, typed by augmentation,
  readable back from the ACL and surfaced by tooling.

This is breaking for every app (every id and grant changes), so it is the
first item of the **0.12 line** (`docs/support.md`: "breaking changes wait
for 0.12") and ships with `tulipes migrate 0.12`. Versions and publication
stay the release owner's call (last sprint item).

## 1. The format, in full

```
users:bo:list                 module=users  scope=bo   resource=list
users:mobile:profile          module=users  scope=mobile resource=profile
users:bo:detail:delete        module=users  scope=bo   resource=detail  extra=delete
hello:web:greet:by-name       4th segment used as a variant of a resource
```

Segment: `[a-z][a-z0-9-]*`. Anything else — `Users:bo:list`, `users:list`,
`users:bo:a:b:c`, `users::list` — is refused at boot with one report line:

```
✖ routes · users: GET /users: rai id "users:read" is invalid — expected
  "module:scope:resource" or "module:scope:resource:extra", lowercase
  segments ([a-z][a-z0-9-]*)
```

Grants (`acl.allow`) accept a full id or a trailing wildcard at any depth:

| grant | covers |
|---|---|
| `*` | everything |
| `users:*` | every users permission, any scope |
| `users:bo:*` | every users permission in the bo scope |
| `users:bo:detail:*` | `users:bo:detail` **and** `users:bo:detail:delete`, … |
| `users:bo:detail:delete` | exactly that |

`*:bo:*` (a scope across modules) is **not** supported: a module grants its
own namespace, as today. Recorded in the backlog.

## 2. Core (`packages/core`)

### 2.1 One grammar module — `src/acl/rai-id.ts` (new)

```ts
export const RAI_SEGMENT = /^[a-z][a-z0-9-]*$/;
export type Rai = `${string}:${string}:${string}`;      // 3+ segments at compile time
export interface RaiParts { module: string; scope: string; resource: string; extra?: string }
export function isRai(id: string): id is Rai            // 3 or 4 valid segments
export function parseRai(id: string): RaiParts          // throws TypeError on an invalid id
export function isGrant(resource: string): boolean      // isRai(x) || "*" || "<1-3 valid segments>:*"
export const RAI_SHAPE = '"module:scope:resource" or "module:scope:resource:extra"'; // for messages
```

Re-exported from `@tulipes/core/acl` and `@tulipes/core/http` so app code
can `parseRai(req.rai.id).scope` without a second import path.

`Rai` is a template-literal type: `rai({ id: "users:read" })` is a **type
error in the editor** before boot runs; `"users:bo:list"` and
`"users:bo:detail:delete"` type-check. (It also admits 5 segments and bad
casing — the runtime check is the authority; the type is a free first line.)

### 2.2 ACL — `src/acl/acl.ts`

- `RESOURCE` regex → `isGrant()` from `rai-id.ts`; message names `RAI_SHAPE`.
- `can(role, permission)`: exact match, `*`, then walk the permission's
  segments from longest prefix to shortest checking `${prefix}:*` (so
  `users:bo:detail:*` grants `users:bo:detail`, and `users:*` grants
  everything under users). Replace the current single-namespace check.
- New `rolesFor(permission): string[]` — the same resolution as `can()`
  but over every role. Three copies of this logic exist today
  (`packages/cli/src/routes.ts`, `packages/spec/src/extract.ts`,
  `example/modules/config/helpers/describe.ts`); all three call this
  instead, so the document can never disagree with the gate.
- Role metadata:

  ```ts
  /** Augment to type the extras your app puts on a role. */
  export interface RoleMeta {}
  export type RoleDefinition = { description?: string } & RoleMeta & Record<string, unknown>;
  export interface RoleRecord extends RoleDefinition { name: string; definedBy: string }

  defineRole(role: string, definition?: RoleDefinition): this   // AclBuilder
  role(name: string): RoleRecord | undefined                     // Acl — frozen copy
  describeRoles(): RoleRecord[]                                  // Acl — load order
  roles(): string[]                                              // unchanged
  ```

  Storage: `#roles: Map<string, RoleRecord>` replaces `Map<string, string>`.
  Validation: `definition` must be a plain object (report line otherwise);
  `name` and `definedBy` keys in it are ignored with a report line. The
  "already defined by" check is unchanged.

### 2.3 RouteInfo and the route scan — `src/http/rai.ts`, `src/http/route-scan.ts`

- `RouteInfo.id: Rai`; doc comment rewritten with the grammar and the
  `users:bo:list` / `users:bo:detail:delete` examples. `RouteRegistry.find`
  keeps `string`.
- `scanRoutes` (`route-scan.ts:55`, where "nonempty string" is checked)
  adds `isRai()`; the message is the one in §1. Scope `routes`, module
  attributed, as the existing lines are.
- `req.rai` unchanged; `parseRai` is the accessor.

### 2.4 Agent actions — `src/agent/define-agent.ts`

`ACTION_ID` → `isRai()`; message `actions[i].id must be a "module:scope:resource[:extra]" permission`.
`toolNameOf` needs no change (`users:bo:detail:delete` → `users_bo_detail_delete`).

### 2.5 Tests (`packages/core/tests`)

  no direct tests today): grammar table (valid/invalid ids and grants),

- Every fixture id in `boot`, `bootstrap`, `http`, `i18n`, `inspection`,

## 4. The reference app and the minimal template

Grants are renamed, never widened: what `user` or `guest` could reach
before, the same role reaches after. Scope rule for the rename: granted to
`guest`/`user` → `web`; admin-only → `bo`.

### `example/modules/auth/module.acl.ts`

```ts
declare module "@tulipes/core/acl" {
  interface RoleMeta { level?: number }   // typed extra, demonstrates augmentation
}

acl
  .defineRole("guest",    { description: "Any request without a valid token" })
  .defineRole("user",     { description: "A signed-in account", level: 1 })
  .defineRole("admin",    { description: "Runs the back office", level: 2 })
  .defineRole("sysadmin", { description: "Administers the deployment and its settings", level: 3 });

acl.allow("guest", "auth:web:login", "auth:web:register", "auth:web:refresh");
acl.allow("user", "auth:web:logout", "auth:web:me", "auth:web:password",
                  "auth:web:sessions", "auth:web:sessions:end");
acl.allow("admin",    "auth:*", "users:*", "hello:*");
acl.allow("sysadmin", "auth:*", "users:*", "hello:*");
```

## 4b. File layout — a best practice, not a boot rule

Routes and controllers are named after the scope first, so a module's
`routes/` folder reads like its surface list. Nothing enforces it: core
keeps loading any `*.routes.ts`, and a module with one surface may keep
`users.routes.ts`.

```
{scope}.{module}[.{extra}].routes.ts            one file per scope
{scope}.{module}[.{extra}].controllers.ts

{scope}/{module}[.{extra}].routes.ts            several files in one scope: a folder,
{scope}/{module}[.{extra}].controllers.ts       and the scope prefix drops off the name
```

```
modules/users/
  routes/
    web.users.routes.ts                 users:web:*   (list, ping, demo)
    bo.users.routes.ts                  users:bo:*    (create, delete, list:deleted)
  controllers/
    web.users.controllers.ts
    bo.users.controllers.ts

modules/hello/                          one scope, several files → the folder form
  routes/web/hello.routes.ts            hello:web:greet, greet:by-name, secret, demo:missing
  routes/web/hello.greetings.routes.ts  hello:web:greetings, greetings:use
  controllers/web/hello.controllers.ts
  controllers/web/hello.greetings.controllers.ts

modules/users/routes/bo.users.passwords.routes.ts   the {extra} slot: a sub-resource
```

What makes it work:

- **Explorer recursion** — `packages/core/src/modules/explorer.ts`
  `listWithSuffix` is non-recursive, so `routes/web/hello.routes.ts` is
  invisible today. `routeFiles` becomes a recursive listing of `routes/`
  (any depth, `*.routes.<ext>` only), sorted by path relative to `routes/`
  so mount order is deterministic. Other collections (`models/`,
  `queues/`, `sockets/`, `bootstrap/`, `agent/`) stay flat; controllers are
  never scanned, so nesting them is free. One test in
  `packages/core/tests/inspection.test.ts` (nested routes file is mounted
  and attributed to the module) and the `tulipes routes` output of the
  reference app as evidence.
- **Scaffold** — `tulipes new <name> --scope web` writes
  `routes/web.<name>.routes.ts` and `controllers/web.<name>.controllers.ts`
  (the flat form; the folder form is documented, not generated).
- **Reference app** — users and auth/config/settings/agent use the flat
  form (`web.auth.routes.ts`, `bo.config.routes.ts`, …); hello uses the
  folder form, so the template demonstrates both. Imports inside the moved
  files are updated (`../../controllers/web/...` from a nested routes
  file). `tulipes migrate 0.12` does **not** rename files; MIGRATING
  shows the layout and says it is optional. The migrator's routes loop
  (`migrateModule`, `readdirSync(routesDir)`) recurses so an app already
  using folders is still rewritten.
- **Guides** — AGENTS.md "where each kind of code belongs" gets the two
  forms with the users/hello examples; `tulipes-endpoint` and
  `tulipes-module` skills show the naming when adding a route; the README
  layout tree in `packages/core/README.md` (line ~118) shows
  `routes/web.users.routes.ts`.

## 5. Migration — `tulipes migrate 0.12`

`packages/cli/src/migrate.ts`: `runMigrate` dispatches on target (`0.11`
keeps today's code; `0.12` is new, in `migrate-0.12.ts`). Flags:
`--scope <s>` (default `web`), the scope inserted into every 2-segment id.

What it rewrites, under `modules/*/`:

- `routes/*.routes.ts` and `agent/*.agent.ts`: `id: "a:b"` → `id: "a:<scope>:b"`.
- `module.acl.ts`: inside `allow(...)` calls, `"a:b"` → `"a:<scope>:b"`;
  `"a:*"` and `"*"` untouched; `defineRole("x")` untouched (metadata is
  optional).
- Any string already at 3+ segments: left as is, listed in the report.
- Anything it cannot parse (computed ids, template strings): `TODO 0.12:`
  comment and a report line, same pattern as the 0.11 migrator.
- Writes `config/migration-0.12.json`: `{ scope, ids: { old: new }, todos }`.

Then the user moves admin-only ids from `web` to `bo` by hand (the report
says so and the MIGRATING section shows the reference app's split).
Tests: `packages/cli/tests/migrate.test.ts` gains a 0.12 fixture (routes,
agent, acl, an already-3-segment id, a computed id).
