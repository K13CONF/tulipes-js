# Release — core 0.12.0-rc.1, the 0.12 line as a candidate

Status: **superseded before a tag.** On 2026-10-13 the owner folded the
environment change and the time zones into the 0.12 line as its next
candidate, [0.12.0-rc.2](./release-0.12.0-rc.2.md); this candidate was
never tagged or published. Kept as the record of what rc.1 would have
been. The release owner had asked on 2026-10-12 to merge the 0.12 work
and publish a new version.
Structural changes open with a prerelease under
[the release procedure](../releasing.md), so this is `0.12.0-rc.1` on
npm's `next` tag; `latest` stays on 0.11.0. Owning item: 0.12-S05 in
[the 0.12 plan](./0.12-plan.md). Release PR:
[#33](https://github.com/kemora13conf/bp-backend-express/pull/33).

## Scope and acceptance

- Core `0.12.0-rc.1` (breaking: RAI ids are `module:scope:resource[:extra]`,
  prefix grants at every depth, role metadata, scope folders under
  `routes/`), `@tulipes/cli` `0.3.0-rc.1` (`tulipes roles`, `--scope` on
  routes, spec and new module, `tulipes migrate 0.12`), `@tulipes/spec`
  `0.4.0-rc.1` (scopes and roles in the documents; core `^0.12.0-rc.1`),
  `@tulipes/mongoose` and `@tulipes/bullmq` `0.2.1-rc.1`,
  `@tulipes/socket.io` `0.1.3-rc.1`, `@tulipes/mcp` and `@tulipes/testing`
  `0.1.1-rc.1`. The last five have no source change; they are republished
  because packing rewrites their core dependency, and their core peer
  range admits `^0.11.0 || ^0.12.0-rc.1`.
- Eight archives, dist-tag `next`.
- Migration: `tulipes migrate 0.12` on an app generated by 0.11.0, the
  rest by the 0.12 section of `packages/core/MIGRATING.md`. The upgrade
  harness now starts from the previous published line (cli 0.2.0 /
  core 0.11.0) and runs exactly that; the 0.10 → 0.11 → 0.12 chain is
  covered by `packages/cli/tests/migrate.test.ts`.
