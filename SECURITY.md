# Security policy

Send vulnerability reports privately to **support@k13conf.com**, the
existing public npm owner contact for `@tulipes/core` (`by_kemora_13`). Include
affected versions, reproduction steps, expected impact and a minimal example.
Omit live credentials and customer data. Do not disclose exploit details in an
issue or pull request before the maintainer has coordinated a fix.

The maintainer will triage reproducible reports, coordinate a fix and disclosure,
and identify affected versions in the release notes. There is no guaranteed
response time or commercial support SLA. The source repository remains private;
this email does not require repository access.

See [supported releases](docs/support.md). The framework is experimental;
passing CI is not a production security certification. Authentication, user
management, settings, logs and process operations generated by the production
preset are application code owned by its operator. Existing applications need
explicit template updates; a framework package upgrade does not rewrite them.

The [production starter security review](docs/security-model.md) records current
controls, tested abuse cases, deployment assumptions and remaining review work.
